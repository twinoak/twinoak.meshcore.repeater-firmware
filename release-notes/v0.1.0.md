**The first release of this firmware.** Until now the only way to get a TwinOak
repeater onto a board was to build it, and the one unit that exists runs a build
somebody flashed by hand. This is the same firmware, built away from home on a
GitHub runner, signed with the release key, and carrying a manifest that says
what every file in it is.

It is a **MeshCore repeater** — upstream's `simple_repeater` from the pin
`repeater-v1.18.0` (`81dbae59`), compiled unmodified and subclassed, so the
radio, the routing, the ACL, the console and the preferences behave exactly as a
stock node's — with four things added: a **link** to the Walter in the other box,
a **clock** that copes with a board that has no RTC, the **radio half of a
MeshMaster exit node**, and an **image that says what it is**. A second role,
**NoiseScope**, is in the same release: the SX1262 spectrum and noise scanner,
flashed in place of the repeater when a site has a noise problem.

A unit flashed with this comes up as a member of the Danish mesh with nobody near
it — 869.618 MHz, the band's own 10 % duty cycle, two-byte path hashes, the four
lines of the Danish standard — and with **an admin password drawn from the
radio's own noise that nobody knows**. Setting your own, before the unit goes
out, is the one thing that has to be done by hand.

## How to flash it

[**docs/flashing.md**](https://github.com/twinoak/twinoak.meshcore.repeater-firmware/blob/v0.1.0/docs/flashing.md)
is the one page: which file is the repeater and which is the scanner, the `.uf2`
and the `.zip` over the adapter's USB-C, the `.bin` through the Walter over SWD,
the base `.hex` for a radio fresh from the factory, what to check afterwards, and
the admin password.
[docs/provisioning.md](https://github.com/twinoak/twinoak.meshcore.repeater-firmware/blob/v0.1.0/docs/provisioning.md)
is what makes a board *this* unit.

## What has been on a board, and what has not

Honestly: **not this image**. The first unit was powered up on 5 November 2026
and its repeater came up on the mesh, on a hand-flashed development build; 26 of
the 97 lines of
[docs/bench.md](https://github.com/twinoak/twinoak.meshcore.repeater-firmware/blob/v0.1.0/docs/bench.md)
are ticked, and the rest need a radio, a phone, a scope or the roof. Everything
else these images do is held by `tools/verify.ps1` — both builds, the host tests,
the rails, the release path rehearsed in full — and not by a board. Two things
in this release have met no hardware at all: the base `.hex`, which no radio has
been provisioned with yet, and the `.bin` over SWD, which only the Walter writes.

## The Walter it goes with

**None yet.** The Walter firmware's first release is its own repository's, and it
has not been tagged; the one Walter that exists runs a development build flashed
by cable. That does not stop this release being used: the box link these images
speak is **1.0**, each image entry says `requires.link_major: 1`, and a Walter is
only ever offered an image of a link major it speaks. Flash the RAK by cable
today; a Walter release will be able to carry the next one over LTE.
