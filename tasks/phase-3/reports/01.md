# p3-01 — roles-and-boards

`src/` is now `src/common/` and `src/roles/repeater/`, an environment compiles
`common/` and exactly one role, and every image carries the 96 bytes of
`spec/FIRMWARE-MANIFEST.md` §4 — built at compile time, read by the firmware's
own `HELLO`, checked by the build, and required by the release. The role, the
board and the band are written in one place (`platformio.ini`'s `[img_*]`
section) and every consumer reads them from there. Done in one session.

```
RAM:   [==        ]  19.2% (used 45324 bytes from 235520 bytes)
Flash: [=====     ]  50.6% (used 412452 bytes from 815104 bytes)
```

(`out/verify/build-repeater_rak4630_single.log`. Against `main`'s 45316 and
412288: **+8 bytes of RAM and +164 of flash**, itemised under *Deviations*.)

### The one seam, and the three couplings it replaced

`common/` may not include a role's header. Three places did:

| Was | Is |
|---|---|
| `target.cpp` called `twinoak::clock::saveBeforeRestart()` in `reboot()`/`powerOff()` | `twinoak::role::beforeRestart()` |
| `target.cpp`'s `BoardSettingsHost` bound the repeater's `Settings` to the link, the clock and power, and `TwinOakSensors` forwarded to it | the four settings functions of `RoleHooks.h`; the host itself moved verbatim to `src/roles/repeater/app/RoleHooks.cpp` |
| `BoardPower.cpp` called `link::raiseAttention` for the two battery thresholds | `role::raiseAttention` |

and one more that was not a role dependency but looked like one:
`BoardPower.h` reached `FILESYSTEM` through upstream's `MyMesh.h`
(`src/roles/repeater/app/UpstreamMyMesh.h`). `UpstreamHeaders.h` now names
`<helpers/IdentityStore.h>` and the core's `<InternalFileSystem.h>` itself.
No behaviour changed with any of the four. There is no weak default for the six
hooks: a role that forgets one does not link.

### The three names

`[img_repeater_rak4630_single]` in `platformio.ini` holds `role`, `board`,
`band`, and the environment interpolates `TWINOAK_ROLE/BOARD/BAND` from it. The
consumers, all of them now reading rather than restating: the environment's own
name, the image descriptor, `HELLO`'s `role`/`board`/`fw_version` (read **out of
the descriptor object**), `HELLO`'s `slot` (the board's row), the version
string's `twinoak-<role>`, `buildinfo.json`, and the manifest's image `id`.
`test/test_image` reads `platformio.ini` and holds each against it;
`tools/release/test_release.py` runs every `[img_*]` section through the release
tooling and checks the `id` and the three file names it produces.

`[band_868]` holds `freq`, `bw`, `sf`, `cr` and `tx_power`; those five flags left
`[nrf52_base]` and the environment, so a second band is a block and not an edit.

## Deviations from the spec or the task

**Flash is +164 bytes and RAM +8, where the task allowed the descriptor's 96.**
The linker map (`out/build/repeater_rak4630_single/firmware.map`) accounts for
all of it, and none of it is the move:

| | bytes |
|---|---|
| `kImageDescriptor`, `.rodata` | **96** (`0x60`, exactly the descriptor) |
| `imageRole`, `imageVersion`, `imageBoard`, `imageSlot`, `.text` | **24** (4 + 8 + 8 + 4) |
| the six role hooks' indirection — a call through `RoleHooks.h` where `target.cpp` and `BoardPower.cpp` had a direct one — and the version string's extra `role` argument | **44** |
| `Descriptor.cpp`'s `build()`, `parse()` and `crc32()` | **0** — in the map's *Discarded input sections*: `0x310`, `0x1b8` and `0x6c` of code that nothing on the board reaches, because the board does not parse descriptors. They are compiled and tested by `[env:native]`, where they are what the fixtures are held against |

RAM's +8 is the alignment of one `.bss` word; nothing new is kept at run time —
reading `HELLO`'s fields out of the descriptor was chosen over parsing it into a
struct precisely so that there is nothing to keep. An earlier draft did parse it
and cost +684 flash and +80 RAM; the map above is the version that shipped.

**The descriptor's CRC is computed in the source, not by a post-link patch.**
The task allowed either and asked which and why. C++11 `constexpr` — one return
statement and recursion — is enough for both the CRC-32 and the zero-padded
string fields at the board's standard (gnu++11, the Adafruit core's), so the
`const` object is right when the compiler emits it. A post-link patch would mean
the bytes the linker produced and the bytes that ship are not the same bytes, and
every checksum downstream — the `.hex`, the `.uf2`, the DFU package, `SHA256SUMS`,
the manifest — would be of the second set; nothing would be left to check the
patch itself. One generator, `fwdesc::byteAt()`, serves both the compile-time
object and the portable `build()` the fixtures are held against, so the CRC has
one definition.

**`src/common/board/target.cpp`'s `TwinOakSensors` stayed in `common/`, and it is
`EnvironmentSensorManager`.** The task puts the board target in `common/`, and
task 02 is to build NoiseScope from "the same board target and power code".
`TwinOakSensors` is upstream's sensor manager, which is MeshCore; a role that does
not compile MeshCore at all cannot use it as it stands. The seam that makes it
movable is in place (the settings are the role's through `RoleHooks.h`, and
`begin()`/`loop()`/`querySensors()` only drive `src/common/power/`), but whether
task 02 keeps the class in `common/`, or splits the hardware half out from behind
upstream's manager, is that task's finding to make against a real second role.
Nothing here is in its way.

**The task says `HELLO`'s `role`, `board` and `slot` "all come from those
three".** `slot` cannot: the descriptor's `slot` says which radio positions an
image may be put in (`0xFF`, any, for a single-RAK image — which is what the
specification's own fixture for this board carries), and `HELLO`'s `slot` says
which position the unit *is* (0). Both follow from the **board** and from nothing
else, so both are columns of one row in `src/common/board/Boards.h`, and
`test_image` holds each against the other. `spec/` and the task do not disagree
here; the task's sentence is shorter than the specification's two fields.

## Decisions taken without asking

1. **Where the clock, the board link and the mesh client went.** The task names
   the repeater's files and `src/clock/` is not among them by name ("the clock
   keeper's wiring" is). The whole of `src/clock/` is the repeater's: the keeper
   exists because a MeshCore node whose clock runs backwards has its adverts
   taken for replays (`docs/ARCHITECTURE.md` §5), which is a mesh problem a
   scanner does not have. `BoardLink` likewise: the codec, the session, the
   dispatcher and the attention machine are common, but the one `Session` and
   the services it is given are a role's — that object is where a role says what
   it can do, and `HELLO`'s `caps` is built from which of them are non-null.
2. **Src-rooted includes.** The move would otherwise have left
   `"../../../common/link/codec/Messages.h"` in the mesh client. Both
   environments already had `src/` on the include path (`target.cpp` used
   `"app/Settings.h"` before this task, the native tests `"link/codec/…"`), so
   this is the same mechanism, applied everywhere.
3. **One `[img_*]` section per image rather than three defines in the
   environment.** The task asks for "three values the build passes as defines
   and everything else reads from there". A define written in `[env:*]` is still
   written twice once `[env:native]` needs the same three; a section is written
   once and interpolated, which is what lets the native environment compile the
   portable half of a real image and what lets `test_image` read the file and
   compare.
4. **The board table carries two slots.** Above.
5. **`433` has no row and no block.** The task says the mechanism gets a test
   with a made-up band; a real `433` block would be a frequency, a duty cycle
   and a power nobody has measured a radio against, and `Bands.h` refuses an
   unknown band rather than defaulting, so shipping one by naming it is not
   possible.
6. **The version string says the role.** `formatVersion` hardcoded
   `twinoak-repeater`; it now takes the role, from the same define. For this
   image the string is byte for byte what it was (`test_version` still asserts
   it), and a scanner will say `twinoak-scanner`.
7. **`requires` carries `link_major` only.** The task asks for
   `requires.link_major`; `spec/FIRMWARE-MANIFEST.md` §2 also allows a minimum
   `walter` version, and nothing in this firmware needs one, so it is absent
   rather than invented.
8. **`firmware.bin` is left in the build directory.** The post-build check has
   to cut the raw application binary out of the `.hex` to look for the
   descriptor; writing it out costs nothing and means a reviewer can run
   `manifestref.py descriptor` on exactly the bytes that were checked.
   `tools/verify.ps1` copies it to `out/build/<env>/` with the rest.

## Not verified here (and why)

The same four lines are now `docs/bench.md` §8, in the order the rig is brought
up.

- **The descriptor of the file about to be flashed, read on the bench.**
  `python spec/tools/manifestref.py descriptor <the release's .bin>` prints one
  descriptor and its offset, and its role, board, band and version are the
  release's. A session can only do this to a file it built itself, which it did
  (above); what the bench adds is that the file which *left* a release is still
  that file.
- **That the unit then says the same thing.** After flashing it,
  `linkcli.py hello`'s `role`, `board` and `fw_version` are the descriptor's and
  `slot` is 0. The code path is tested natively against the same bytes
  (`test_image`'s `Names.TheImageDescriptorOfThisBuildCarriesThem`), but no
  session can flash a board or speak the link.
- **`sensor get fw.version` on the USB console** reads
  `twinoak-repeater <version> on MeshCore <tag> (<pin>)` with that same version.
  Needs the console.
- **That the Walter reads the descriptor from the image it downloads**, compares
  it with the manifest entry and with the radio position it is about to flash,
  and refuses an image for another board or band. That is
  `twinoak.meshcore.walter-firmware`'s own tests against the same fixtures
  (`spec/fixtures/manifest/`), as the task says; this repository has produced the
  bytes those tests will read.

Nothing above needs a radio, a second node or the roof antenna: the descriptor,
the names and the band are all settled before a packet is sent.
