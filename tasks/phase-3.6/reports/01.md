**What the audit of deliverable 4 found, and what came of it.**

- `actions/checkout`'s `clean: true` runs `git clean -ffdx`, and `-x` takes the ignored
  directories too, so `.pio/` (the build, and the dependencies PlatformIO clones — MeshCore among
  them, at whatever pin the branch that ran here last had) and `out/` go before the job starts.
  That is now asserted rather than assumed, in a step of its own: a stale checkout would otherwise
  build the wrong MeshCore and say nothing.
- Outside the workspace, `ci.yml` writes to `~/.platformio` and `~/.cache/pip` and nowhere else;
  that is the whole reason the cache steps can be skipped at home. No step opens a port on the
  host, starts a container, or leaves anything running — so there is nothing to tear down
  `if: always()` here, which is the one lesson of meshmaster.dk's `35a5d2a` this repository does
  not need.
- `upstream.yml` did use `/tmp`: `git clone … /tmp/meshcore`, `/tmp/body.md`, `/tmp/upstream.md`.
  On a GitHub-hosted runner `/tmp` was that job's alone; on a shared one, `git clone` into a
  directory last week's run left behind fails. All three are `$RUNNER_TEMP` now, which the runner
  empties at the start of every job — exactly what `/tmp` was being trusted for.
- What the two jobs call: `node` (every action), `pwsh`, `bash`, `git`, `curl`, `tar`,
  `sed`/`awk`/`date`, and `gh` for `upstream.yml`. **`zip` is not called by any job of this
  repository** — the DFU `.zip` is written by `adafruit-nrfutil` out of `~/.platformio` and the
  run's artifact by `upload-artifact` in Node — so nothing installs it, and `ci.yml` says so where
  somebody would look. `jq` is only in `release.yml`, which stays on GitHub's runners.
  Of the list, `g++` is the one the job installs when it is missing; see the decisions below. On
  `unraid-3` nothing was missing: the step printed no `installing:` line and `tools/verify.ps1`
  reported `native … with this machine's g++`.

## Decisions taken without asking

1. **The guard is a step of `ci.yml`, not a step of `tools/verify.ps1`.** The task says "a step
   early in `ci.yml`", and that is also where it is worth the most: it fails in three seconds,
   before a toolchain is fetched, with a GitHub annotation on the offending line. The cost is that
   "CI runs `tools/verify.ps1` and nothing else" is now "the guard, then `tools/verify.ps1`". It
   is a command as well — `pwsh -File tools/ci/check-runners.ps1` — so a session can run it before
   pushing, as this one did. `docs/upstream.md`'s sentence about what a green bump means is left
   alone: the guard says nothing about the firmware.
2. **`g++` is installed by the job when it is missing, rather than letting the fallback happen.**
   Without a host compiler `tools/verify.ps1` runs the native tests and the link loop in a
   `python:3.11-slim` container — and a container started from *inside* the runner's own container
   would bind-mount a path the Docker daemon's host does not have. Installing the compiler keeps
   that step on the host, as it is on GitHub's runners, and keeps the local and the CI run the same
   run. It turned out to be there already.
3. **`pwsh` is not installed, only required.** It is a package feed rather than a package. A runner
   without it fails in that step, naming itself, instead of failing inside `Verify`.
4. **What the guard considers right.** At home: exactly the two labels `self-hosted` and `unraid`,
   in any order, and nothing besides. Away: one label, of `ubuntu-*`, `windows-*` or `macos-*`
   (so `self-hosted` can never satisfy it). A job with neither `runs-on` nor `uses:` fails, and a
   workflow file the reader finds **no** job in fails too — a guard that quietly matches nothing is
   worse than none. The reader is line-based, skips the body of a block scalar (so a `run:` line
   that says `runs-on` is not a job's), and understands both the flow (`[a, b]`) and the block
   (`- a`) sequence forms. Checked against a real YAML parse of all three files in a container:
   `ci {'verify': ['self-hosted', 'unraid']}`, `release {'ci-green': 'ubuntu-latest', 'build':
   'ubuntu-latest', 'publish': 'ubuntu-latest'}`, `upstream {'bump': ['self-hosted', 'unraid']}` —
   the same answer the guard gives.
5. **The rule lives in the script, in prose, once.** `ci.yml`, `release.yml`, `README.md`,
   `docs/release.md` and `keys/README.md` point at it rather than restating the reason.

**One thing the local run caught, worth recording.** The first draft of `ci.yml`'s comment on the
