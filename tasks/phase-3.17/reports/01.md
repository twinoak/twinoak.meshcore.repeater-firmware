# p3.17-01 — a settle by default

Phase 3.16's task 02 built the settle and left the default alone until somebody measured it.
Four NoiseScope sessions on the unit at Bellevue measured it (`tasks/phase-3.16/FOLLOWUPS.md`,
*What the garden said: sessions 6 to 9*), so this task moved the default: **a `scope` that names
no settle stands 500 µs on each segment's first point, `0` is how a line asks for none, and the
`ack` now says which on every `scope`.** Nothing else of a `scope` moved — the points, the
segments, the words, `us`, `usx` and `dev` are `main`'s, held by tests this branch did not touch.

The two lines a session has to type to see it, printed by this firmware's own `planScope()` and
`scopeAckMessage()` (`out/p3.17-01/ack-lines.txt`):

```
scope 840 900 0 467 1000           n=129 step=465.1163kHz rbw=467.0kHz seg=2 cov=1.004 interval=1000ms sweep=2ms settle=500us
scope 840 900 0 467 1000 max 32 0  n=129 step=465.1163kHz rbw=467.0kHz seg=2 cov=1.004 interval=1000ms sweep=1ms settle=0us
```

**No board and no session.** Nothing on this machine can see the first points of a segment, so
the whole of *What only the unit can show* is below under *Not verified here*, and
`tools/noisescope/lists/garden-d.txt` is now that session's program: its first two steps are
exactly those two lines.

## Decisions taken without asking

- **Absent is `0xFFFFFFFF` and is resolved in `planScope()`.** The alternative was a second
  `bool settle_named` field beside the number. The sentinel keeps the struct one field wide, puts
  the decision in one line of one function, and is deliberately **above** `kScopeSettleMaxUs` so
  that an unresolved request can never be mistaken for a legal settle — a test asserts that
  ordering.
- **A ninth word that is not a number reads as none, not as the default.** `asU32()` falls back
  only for a missing word, so `strtoul("nope")` is 0 and 0 is none. That is the reading every
  other number on a `scope` line gets, and it is what the comment in `parseScope()` says; nothing
  in the spec or the task covers a ninth word that is not a number.
- **The `ack`'s order is `segw=` (only when the width is not 32 MHz), then `settle=` always, then
  `reg=` and `gain=`.** The task fixes that `segw=` stays conditional and `settle=` becomes
  unconditional, but not the order; keeping each where phase 3.16's task 02 put it means a reader
  written for that task's lines still finds both.
- **Every row of `scope_plans.json` carries `settle_us`, not only the new pair.** The table is
  what holds the two copies of the arithmetic equal, and the default is part of that arithmetic
  now; the field on one row only would have left twenty rows saying nothing about it. Both tests
  compare it, so neither copy can move the default without the other noticing.
- **`plan_of_frame()`'s own `settle_us` default stays 0.** A frame carries no settle, so a capture
  with no `ack` to read one out of is read as a `scope` that stood on nothing — which is what
  every line typed before this task did, and what every capture now in
  `tools/noisescope/captures/` is.
- **`echoes.py --steps` prints the settle on every row and `segw` only when it is not 32 MHz**,
  which is the `ack`'s own rule. It used to print both or neither.
- **`tools/bench/fakes.py`'s fake scanner `ack` was left as it is.** It already answers
  `sweep=86ms` and no `segw=`/`settle=`, which no firmware since phase 3.16's task 02 says; it is
  a fake for the bench tool's own tests and nothing parses those two numbers out of it. Changing
  it is not this task's, and it would have been a change with no test behind it.
- **The help text gained four words, the usage line none.** `help` now reads
  `settle_us <= 20000, none = 500;` on its own line (and `scope off` moved to the next), which is
  where a person on a console reads a default. `usageOf(kVerbScope)` is the grammar a line the
  parser cannot read at all is answered with and is already near the `ack`'s length bound, so it
  was left alone.

## Not verified here (and why)

Nothing on this machine can see a segment's first point: `tools/bench/bench.py status` was not
run, no port was opened, nothing was flashed and `bench restore` was not run. There was no board
and no NoiseScope session in the checkout.

* **The two lines, on the unit at Bellevue — `tools/noisescope/lists/garden-d.txt`, steps 1 and
  2.** After a release carrying this task and *Fetch a scanner image* on the unit:
  `python tools/noisescope/hunt.py --sessions tools/noisescope/lists/garden-d.txt`, paste the five
  lines into the form on the session's page, and an hour later *Download the lines* into
  `tools/noisescope/captures/garden/`, then
  `python tools/noisescope/echoes.py --steps <file> --carrier 869.618`. **What says it worked:**
  step 1 (`scope 840 900 0 467 1000 max 32 0`) has the first six points of each of its two
  segments standing 13 to 36 dB over the floor in the lit frames, as session 9 read them
  (−64.5, −74.5, −74.5, −78.5, −88.5, −91.5 dBm against a floor of −104.5); step 2
  (`scope 840 900 0 467 1000`, the same line with nothing typed) has them **at the floor**, in the
  lit frames and the quiet ones. The pair `--steps` prints for those two says `500 us -> 0 us` and
  is the one to read. `dev` should be `0000` throughout.
* **That the `ack` of every step says its settle.** Everything above is read out of the `ack` —
  `settle=500us` on step 2 and `settle=0us` on step 1 — so a download whose acks are missing
  cannot be read as a pair at all (`--steps` says so per step). The acks' bytes are held by a host
  test; whether meshmaster.dk's *Download the lines* carries them is still the first download's
  to say (`tasks/phase-3.16/reports/04.md`).
* **What the default costs in sweeps a second, on the unit.** Session 9 measured 29.1 a second
  with no settle and 28.0 with 500 µs for two segments at 467 kHz; `sps` of steps 1 and 2 of this
  session is that measurement made again, with the number in the firmware rather than typed. A
  `sps` on step 2 that is under step 1's by much more than that would be a finding about the
  default and not about the sweep.
* **The narrow pair, steps 4 and 5** (`scope 863 876 250 58.6 1000 max 32 0` and `… max 32 1000`):
  one segment, so this is the *before every sweep* half — the stand `serviceScope()` makes between
  two sweeps of a segment that never re-arms. The one first point at the floor in step 5 and
  standing in step 4.
* **The image check of `docs/bench.md` §9 has still never been walked** (22 October), and this
  task's name is now on it with the four before it. One carrier, a wide `scope`, one peak — the
  bench's half, and it needs the board, the generator and `"rf": "antenna"` in
  `bench.local.json`.
